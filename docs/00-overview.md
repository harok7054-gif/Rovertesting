# 1 프로젝트 결과와 시스템 구조

## 목표와 결과

이 프로젝트는 Rover가 제공하는 서로 다른 통신 경로를 PC에서 확인하고 하나의 응용으로 연결하는 작업이다. 처음에는 Ethernet DDS 패킷과 센서 상태를 확인했고, 이후 gRPC 고수준 API, Wi-Fi 카메라, 마이크 데이터, 저장 음성 재생을 차례로 연결했다. 마지막 응용은 카메라에서 사람이 보이면 미리 등록한 인사말을 로버 스피커에서 재생하는 것이다.

모터 제어와 영상·음성 기능은 같은 API가 아니다. DDS로 모터 온도가 들어온다고 gRPC 권한이 확보된 것은 아니고, 카메라 영상이 보인다고 음성용 DDS 인터페이스가 살아 있는 것도 아니다. 각 계층을 분리하여 시험한 것이 문제를 해결하는 핵심이었다.

## 전체 연결

~~~mermaid
flowchart TD
  PC["Ubuntu 개발 PC"] --> DDS["Ethernet DDS"]
  DDS --> Motor["모터 상태와 저수준 명령"]
  DDS --> Mic["마이크 PCM 수신"]
  PC --> RPC["gRPC 50051"]
  RPC --> Motion["상태와 고수준 동작"]
  PC --> Keeper["카메라 SDK 세션"]
  Keeper --> RTSP["RTSP 8554"]
  RTSP --> YOLO["YOLO person 검출"]
  YOLO --> Gate["연속 검출과 반복 간격"]
  Gate --> HTTP["HTTP 22000"]
  HTTP --> Speaker["등록 음성 ID 재생"]
~~~

카메라는 RobotClient 객체로 접근하지만, 영상 데이터 자체는 gRPC 스트림으로 전달되지 않는다. SDK가 스트림을 열고 유지하면 FFmpeg 또는 OpenCV가 RTSP 주소에서 프레임을 받는다. 현재 공식 SDK는 영상 시작과 종료에 HTTP 22000 서비스도 사용한다.

## 연결 주소와 역할

| 용도 | 실습 주소 또는 값 | 설명 |
|---|---|---|
| 유선 로봇 | 192.168.5.2 | DDS 센서와 저수준 명령 |
| 유선 PC | 192.168.5.x/24 | 로봇과 다른 미사용 호스트 주소 |
| 무선 로봇 | 192.168.1.6 | 로버 Wi-Fi에서 접근 |
| gRPC | 50051 TCP | 상태 조회와 동작 요청 |
| RTSP | 8554 TCP | 카메라 스트림 수신 |
| HTTP | 22000 TCP | 영상 제어와 음성 목록·업로드·재생 |
| DDS Domain | 0 | 실습의 동일 통신 도메인 |

IP는 이번 실습의 실제 값이다. 다른 펌웨어와 네트워크에서는 반환 URI와 라우팅 결과를 우선한다. DDS 포트는 발견과 데이터 전달 규칙 및 설정에 따라 달라지므로 50051을 DDS 포트로 사용하지 않는다.

## 완료 수준

| 결과 | 수준 | 근거와 해석 |
|---|---|---|
| 관절각과 온도 | 실기 확인 | 10월 8일 성공 보고 |
| DDS 및 gRPC 기본 제어 | 사용자 완료 보고 | 10월 16일 두 제어 경로 확인; 상세 관절 궤적 수치는 별도 |
| 고수준 상태와 동작 목록 | 원본 응답 확인 | 10월 20일 WALK, speed ratio 30, miniQuad, 동작 27개 |
| 전방 카메라 | 실기 확인 | ffplay 재생 성공 |
| 마이크 | 원본 파일 및 수치 확인 | 16 kHz mono PCM16, 15초 |
| 인사말 등록과 재생 | 패킷 확인 | greeting_original 업로드 완료와 같은 ID 재생 상태 |
| YOLO 인식 | 화면 로그 확인 | 사람 수 변화와 PERSON_CONFIRMED 이벤트 |
| 사람 인식과 음성 통합 | 사용자 완료 보고 | 본 요청에서 통합 시험 완료를 명시 |
| 최신 HTTP v4의 wolf 재생 | 별도 버전 확인 필요 | 기존 v4 설명은 현장 확인 전 상태이며 wolf 청취 로그 없음 |

작업 전체의 완료 보고와 특정 코드 버전의 계측 결과는 구분한다. 제공된 v4는 가장 최근의 재현 코드이며 로컬 모의 서버 시험을 포함한다. 정확한 성공률, 평균 지연, 오검출률과 장시간 안정성 수치를 측정한 것으로 제시하지 않는다.

## VLA 단계의 의미

현재 구현은 Vision으로 사람을 검출하고 규칙으로 Action인 음성 재생을 선택한다. 녹음된 자연어 인사말은 출력 콘텐츠이며 Language 입력을 해석하는 모델은 없다. 작품 제목에서는 시각 음성 통합 또는 VLA 기초 통합 시험으로 표현할 수 있다. 자유로운 언어 명령을 이해하거나 학습 정책으로 보행을 생성하는 VLA 완성 시스템으로 소개하지 않는다.
