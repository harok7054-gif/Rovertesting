## 중요한 오류와 수정 근거

| 증상 | 원인 판단 | 대응 |
|---|---|---|
| No module named grpc | 다른 Python 선택 가능성 | 성공한 .venv_grpc의 절대경로 확인 |
| CameraId 없음 | 오래된 SDK에 영상 API 없음 | 별도 카메라 SDK와 환경 |
| 생성 proto import 실패 | clone만으로 설치 완료되지 않음 | pip 빌드·설치 |
| DDS 참여자는 보이나 데이터 없음 | 타입·QoS·NIC·방화벽 계층 점검 필요 | 한 요소씩 상태 구독으로 검증 |
| NIC does not match | 설정 이름이 현재 인터페이스에 없음 | ip -br link, XML 이름 비교 |
| kill_robot 파일 없음 | examples 경로 누락 | 실제 파일 위치 확인 |
| PERMISSION_DENIED | 서버가 요청을 거절 | 실패한 RPC 확인, 승인된 설정 적용 |
| RTSP 404 | 활성 스트림 또는 경로 문제 | SDK open과 유지 확인 |
| curl 26 | 로컬 파일을 열지 못함 | 정확한 AUDIO_FILE과 파일 존재 확인 |
| 업로드 후 다른 소리 | 예전 재생 ID 사용 | 목록에서 새 name과 id 매칭 |
| DDS 음성 오류로 전체 종료 | 초기 실행기의 오류 전파 | v3 감지 유지, v4 HTTP 경로 |
| 재생 POST timeout | 수락 후 응답만 유실됐을 가능성 | 즉시 재전송 없이 상태 조회 |

방화벽이 원인이었는지, 어댑터 변경이 직접 해결 원인이었는지 등은 최종 설정 기록 없이 확정하지 않는다. 제조사의 내부 유지관리 도구와 장치 비밀정보를 재배포하지 않고, 승인된 설정 변경 후 DDS 수신이 어떻게 달라졌는지를 시험 기록에 남긴다.

## 로컬 시험이 다루는 것

기존 `test_http_voice.py`의 10개 시험은 이름에서 ID 선택, 같은 ID의 재생 상태 확인, 8초 간격, 재생 중 건너뛰기, 불완전 상태 응답 차단, 네트워크 오류 뒤 회복, POST 응답 유실 시 즉시 중복 재전송 방지, 중복 이름 거절, 사람 소실 중 취소, 종료 후 요청 차단을 다룬다.

테스트 서버는 127.0.0.1의 임의 포트를 사용한다. 테스트 과정의 VOICE_ERROR 출력 일부는 실패 상황을 의도적으로 주입한 결과다. 최종 unittest 결과의 OK와 실패 수를 함께 확인한다.

## 측정값으로 제시하지 않는 항목

영상의 실제 해상도·FPS·코덱, 인식 precision·recall, 실제 사람별 인사 성공률, 카메라 촬영에서 음성까지의 종단 지연, 제어 루프의 정확한 주기, 관절 궤적 오차, 파일의 재부팅 후 유지 여부는 이 실험 자료로 정량 확정하지 않는다.

현재 시스템은 시각 인식과 로봇 출력의 연결 가능성을 검증하는 통합 시험이다. 전시나 장시간 운용에 사용하려면 아래 형식으로 세션별 결과를 추가한다.

| 기록 항목 | 기입 내용 |
|---|---|
| 실행 식별 | 날짜, 코드 commit, SDK commit |
| 장치 | 기종, 펌웨어, PC CPU, NIC |
| 조건 | 거리, 조명, 사람 수, Wi-Fi 상태 |
| 입력 | 모델 hash, imgsz, conf, 실제 URI |
| 음성 | 등록 이름과 ID, 파일 hash |
| 결과 | 시도 횟수, 성공 횟수, 오검출, 누락 |
| 시간 | 수신, 판단, 요청, 음향 시작 시각 |
| 종료 | 정상 종료 또는 실패 원인 |
